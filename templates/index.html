      Live heap allocations after each call
      Bytes the process heaps hold allocated right now, against bytes they merely keep committed. Live growth is a leak; committed-only growth is the allocator holding freed pages.
      Memory held after each call
      Private bytes is the commit charge, the reliable leak signal. Working set is the resident part and the OS may trim it at any time.
      Change in private bytes per call
      Each column is one call's net effect. A steady run of positive columns is a leak; isolated spikes are usually heap arena growth or a lazy cache.
      Transient memory during each call
      In-call high-water mark minus what was still held on return, sampled every 5 ms while the call runs. This is scratch memory the DLL needs but gives back.
      Leak sites
      Allocations made by the DLL after warmup that were never freed, grouped by call stack. A site that keeps a block from nearly every call is a leak; a site seen in one call is a lazy initialisation.
